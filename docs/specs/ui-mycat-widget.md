# mycat 桌面小组件与“Jarvis”体验草案

## 目标
- 在 macOS 桌面提供常驻小组件（menubar + 可浮动波形窗），方便唤起语音对话。
- 与语音守护进程联动，展示实时波形/字幕/动作时间线，让用户有“Jarvis”式反馈。

## 形态
- Menubar 图标：单击开启/结束通话，长按=按住说话；下拉菜单显示最近动作与模型路由状态。
- 浮动波形窗：可拖拽，显示音量波动、实时字幕；支持最小化为胶囊条。
- 审批弹框：高危动作时以原生 macOS sheet/通知形式请求同意。

## 关键状态
- idle / listening / thinking / acting / needs-approval / error。
- 每个状态对应的视觉：波形颜色/频闪、字幕提示、按钮启用态。

## 交互要点
- 首次启动：请求麦克风/屏幕录制授权；提示“隐私/只在本机处理”信息。
- 按住说话：松手即发送；VAD 自动切分；超时自动停止录制。
- 模型卡片快捷切换：下拉菜单中切换“本地/云”路由，展示 p95 延迟+成本估算。
- 审批：高危操作以弹窗+语音播报；拒绝默认；用户可在 10s 内口头或点击确认。

## 动效参考
- 波形：类似 ChatGPT macOS 客户端/苹果 Siri 动态波形；振幅跟随音量。
- 转场：从 listening→thinking 时，波形颜色渐变并增加轻微发光；acting 时在时间线上闪动节点。

## 技术栈建议
- Electron menubar + React (Next.js 共享组件)；波形用 Canvas/WebGL；系统弹框用 macOS 原生 sheet。
- 状态管理：Zustand 或 Jotai，状态驱动 UI；通过 WebSocket 订阅守护进程事件。

## 度量
- 用户点击/语音唤起次数；完成任务成功率；审批同意/拒绝比；波形窗 CPU 占用（目标 <5% 常态）。

## 未决问题
- 是否允许屏幕实时共享辅助视觉理解？（需要额外权限与隐私提示。）
- 是否需要离线模式完全不访问云端？（默认本地 ASR/TTS + 可选本地 LLM 时开启。）
